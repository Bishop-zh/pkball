# PKBall UI 实机评审与 GPT-6 Sol 执行清单

评审日期：2026-09-30。
项目：`C:\code\GameMake\PKBall`。
本次为截图评审，未修改游戏代码。通过实际运行窗口查看主菜单、事件结果、事件选择、商店、背包选中状态、角色数值、对手详情、战斗准备与进行中、三档怪物选择。截图由 Computer Use 实时捕获，不是设计效果图。现有存档从第 42 天推进到第 43 天，最终停留在野怪选择页。

## 目标与保留项

保留球形卡通角色、深蓝灰底色、少量金色装饰，以及事件选择与整理界面的分离。
保留整理界面的左侧装备、右侧当前事件、底部背包结构。
本轮只优化 UI 表现与交互，不改战斗数值、经济规则、随机池或存档格式。
核心目标：玩家先看到行动目标，再看到决策需要的数据；图标可辨认、价格明确、文本无裁切；装饰服务于层级。

## 已确认问题与改法

### 1. 战斗 HUD：P0

- 实际截图中，底部操作提示和局内生命文字超出窗口底边，被裁切。
- 时间、碰撞次数、质量、目标速度等文字靠在场地顶部；开发调试信息占据正式界面。
- 玩家和敌人头像、名字、生命条的对齐关系不统一；敌人文字和血条横向距离较大。
- 战斗时“新的一局”“重开”与倍速按钮并列，操作层级不合理。

修改：建立固定顶部 HUD 安全区和底部操作区，竞技场视口避开它们。顶部左右各用统一的头像、名称、生命数值与血条组合，能量条加清楚的标签；中间只保留战斗计时。质量、目标速度、碰撞计数移到调试开关。战斗主操作保留倍速和菜单，重新开局等操作收进菜单。瞄准阶段显示一句发射提示，战斗开始后收起。

### 2. 全局字号与缩放：P0

- 当前窗口中，装备、商店说明、右上资源、背包详情均明显偏小。
- 面板和装饰很大，但信息仍按原来的小字号显示。
- 出售按钮实际出现“出售 · 14”和“金”分成两行。

修改：建立统一字号、间距、按钮高度规则，优先保证实际显示尺寸可读。1920×1080 参考画布可从标题 32–36、正文 24–26、辅助文字 20–22 开始试调；在缩小窗口中检查实际结果，不将参考画布数值当成最终可读性的证明。价格、短按钮标签不换行；长说明使用稳定宽度并允许展开。不要依靠无限缩小字体消除溢出。

### 3. 商店：P0

- 每张商品底图右侧有一个空白金色牌，看上去像按钮，但价格写在另一侧正文中。
- 长生产说明延伸到金色牌上，视觉冲突。
- 图标偏小、金属边框偏厚，商品辨识度弱；部分说明出现 Melee 等英文。
- “出售背包中的金矿”在商店操作区出现，和背包出售功能分散。

修改：商品使用“较大图标 + 名称与等级 + 两行核心效果 + 右侧明确价格”的固定布局。将金色牌真正用作价格区域，或者换成没有假按钮的背景切片；价格和说明永不共用一个区域。商品仍支持点击购买和拖拽购买。已售出、买不起、可购买状态明确区分。刷新放在商店标题附近，批量出售金矿归入背包工具区。全中文显示攻击类型和冷却。

### 4. 背包与角色数值：P0

- 背包格是横向小文本框，图标很小，“空”字重复占据大量注意力。
- 右侧详情区域又窄又矮；所选物品说明和左侧装备区的悬停说明重复，并且距离鼠标远。
- 数值切换后，长属性列表被放入底部矮条，仅能同时看到少数行，横向空间大量闲置，滚动入口不明显。
- 非针剂选中时仍显示“使用针剂”；没有可领产物时仍常驻“领取针剂 · 0”。

修改：底部保留两排背包；图标作为格内主体，等级放角标，名称仅显示一行。空格用轻底色即可。物品详情统一成靠近鼠标且不出屏的浮层，或选中后稳定显示的详情区，避免两处重复说明。属性页改为覆盖装备区的独立抽屉/较高面板，核心属性用两列展示，来源明细可展开；不要复用底部背包矮条承载长列表。使用按钮随道具类型显示；无收益的领取操作隐藏或缩成低优先级状态。

### 5. 角色装备环：P1

- 十格情况下，位置名、道具名、等级与小图标都挤在小矩形中，像调试格子。
- 格位加成主要靠颜色区分；用户无法直接知道颜色代表什么。
- 角色底板和“拖针剂到此”永久占位，说明文字重复。
- 满格时仍有升级格位按钮占据底部重要位置，至少需要明确满级状态。

修改：保留环状关系，但放大道具图标；格内只显示图标、等级角标和简短状态标记。位置名按需在悬停时显示。特殊格位加一个小符号，并在详情说明具体效果，避免仅靠颜色。拖针剂时才高亮角色目标并显示提示。满级后将升级按钮收起或显示静态“10/10 格”，不再作为高亮操作。

### 6. 事件选择与结果：P1

- 两个入口已正确独立，但大卡片只有几行小字，边框占据较大视觉权重。
- 已知是金币补给、药剂工坊时，标题却仍写“随机事件”，不利于快速决策。
- 结果页只写通用的“事件已结算”，右侧大片空白；有一次显示的是恢复存档提示，未清楚解释本次收益。

修改：事件卡用具体事件名、一个代表图标、一句收益说明和明确行动。例：“金币补给 / +27 金币 / 领取补给”。商店卡写“商店 / 4 件商品 / 进入商店”。减薄卡边，卡片整体可点击并有悬停反馈。结果区显示本次获得的金币、物品或格位效果及数量，使用紧凑奖励区域；通用教学文字改成首次提示。若需要结果数据，建立界面用的结果摘要，不从 Notice 临时文案反推奖励。

### 7. 怪物选择与详情：P1

- 三卡同档比较的结构明确，可以保留。
- 三张卡的边框完全相同，仅靠很小的徽章和正文区分难度。
- 头像和正文之间有空隙，属性、打法、装备、奖励却挤在同一段居中文字里。
- 装备仅写名称，快速识别和查看具体效果不方便。

修改：卡顶部显示完整的“普通 / 精英 / 首领”标签；辅以小面积颜色区分。头像下是怪物名，随后生命/速度的两列属性，再放打法标签、装备图标行、奖励。正文左对齐，奖励固定在同一基线。装备图标可悬停查看详情。选择卡直接选择怪物，但查看道具详情不能误触选择。所选对手详情维持现有头像和装备行结构，扩大信息本身而非增加边框。

### 8. 主菜单：P1

- 主菜单美术主题统一，但未开放的休闲、双人模式占据中心大量空间。
- 左侧图鉴、排行也显示为按钮，却暂时不能使用。
- 有已有存档时主按钮仍写“开始一场冒险”，实际继续当前进度，语义不清楚。
- 当前无尽存档显示“18/10”“19/10 胜场”，看上去像计数异常。

修改：当前只突出一个“继续冒险/开始匹配”入口。未开放模式、图鉴与排行集中为低对比的小区域或暂时隐藏。主菜单档案只显示有用进度；无尽状态明确写“无尽 · 第 43 天 · 累计 19 胜”。角色外观区保留三种选择，但减轻头像外框，清楚标记选中项。删除占屏的开发实现说明，必要时保留简短“当前为本地对战”。

### 9. 顶部导航与统一风格：P1

- “PK BALL / 准备阶段”标题占据较宽空间，日期、资源、生命、经验却挤在右上角。
- 每个阶段统一写“前往下一阶段”，玩家需要记忆接下来去哪里。
- 金色卡框、银色商品框、青色胶囊按钮、红金长箭头和直角底板同时出现，语言过多。

修改：顶部缩成一条清晰状态栏：日程进度、金币、局内生命、胜场；次要经验和产物数量降低优先级。用简短六节点进度展示今日位置。主按钮采用“前往野怪 / 进入下一事件 / 开始对战”等结果导向文案。组件限定为三层：页面底板、内容卡/格子、主操作。只保留一种主按钮和一种次按钮；装饰资源使用正确九宫格切片和固定边缘尺寸，禁止按不同宽高直接拉伸装饰。

## Sol 推荐实施顺序

1. 修复战斗 HUD 锚点、底部裁切、按钮换行和全局缩放。
2. 统一字体、间距、按钮与轻量底板，清理空白假按钮和开发文本。
3. 重做商品卡、图标优先的背包格、独立数值面板和统一道具详情。
4. 优化装备环、事件结果、怪物卡的信息顺序。
5. 精简主菜单，再检查所有入口与当前可用功能一致。

重点文件：`Assets/PKBall/Scripts/UI/PrototypePreparationUI.cs`、`PrototypeHud.cs`、`PrototypeMainMenuUI.cs`、`PrototypeUiSkin.cs`。
优先将商品卡、格子、按钮、提示浮层抽成可复用组件；避免继续在按名称判断的通用 Button 方法里叠加大量例外。布局使用明确的父容器与锚点、LayoutGroup/LayoutElement；数据更新与界面布局分开。

## 必须通过的验收

- 1920×1080、1600×900、1280×720 三种窗口下实机截图；另检查一次非 16:9 窗口，确认无越界。
- 覆盖主菜单、两个事件选择、事件奖励、商店、背包选中、数值页、三怪选择、对手详情、瞄准、战斗中、结算状态。
- 无文字裁切、无价格换行、无按钮覆盖文字；短按钮标签保持一行。
- 10 格全部装备、背包满、最长道具名称、四级道具、金币不足、已售出、无可领产物时均正常。
- 事件选择页不混入背包和商店；商店仅在选择进入后显示。
- 所有可见按钮含义明确，装饰不得伪装成无功能按钮。
- 拖拽购买、装备、合成、针剂使用、出售和滚轮等级预览保持可用。
- 选择怪物前能看见难度、关键属性、装备和收益；查看装备不能误选怪物。
- 最终提交真实运行截图，并说明修复前后的可见差异。编译成功不能替代视觉验收。
