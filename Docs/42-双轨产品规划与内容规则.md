# 双轨产品规划与内容规则

2026-10-13，主策划提案与本批实施边界。

## 产品方向

PKBall 的共同资产是“一个有故事的角色、一组来自其形象的道具、一场能看懂的自动战斗”。主播模式负责验证角色有没有观赏性、形成视频账号内容；冒险与多人构筑负责让玩家亲手组合这些道具。视频里出现的机制必须能在同一战斗系统复现。

第一阶段重点是主播内容。先做角色关系、清晰触发和可复用的录制预设，再依据试录结果补立绘与特色动作。暂不为每个角色写独立战斗分支，不提前承诺网络排位已可玩。

多人方向建议先做异步构筑对战：玩家完成每日经营后，与同天数、同规则版本的玩家快照进行1对1自动战斗；一局由多位玩家的快照参与匹配。之后再验证8人同场赛事房间。多人参与不要求立刻把当前双角色战场扩成多人混战；混战涉及目标选择、范围效果和读屏，是独立玩法成本。

这是本项目的设计选择，不是对参考游戏具体规则的复刻。当前 `PrototypeGhostPlayerProvider` 仍返回本地模拟对手，不是真实玩家匹配服务。

## 内容来源规则

按“故事身份 → 可见动作 → 招牌道具 → 可组合效果 → 对抗窗口”建立角色。角色名不能直接引入隐藏特权：冰晶不自动冻结，雷电不自动眩晕，死神不保证斩杀，拾荒不自动吞并，战旗不自动给队友加成。

普通身份拥有清晰的一项本领；精英拥有两项联动；首领拥有核心遗物或完整攻防循环。故事强度首先体现在档位、出场阶段和装备组合，所有战斗数值必须写进实际配置。影片可以跨档挑战，但必须展示档位与装备等级。

多人标准化与故事档分开：未来统一起始本体300生命、相同金币和格位资源、无跨局永久数值继承；道具只在本局成长。角色背景与外观不赠送额外战力。首领固定四级遗物不能与一级商店装同价投放，先作为冒险目标；是否进入排位以及其价格，须单独验证。

## 本批已落地

- 17个现有怪物补全背景、战斗看点、弱点和主播配装；9个早期怪物由2～3件通用装补成6件主题装，保持原候选索引与稳定ID。
- 6个新主播构筑：荆棘园丁、拾荒机匠、霜镜游侠、逐雷信使、余火司炉、失冠禁卫。复用已有外观，未生成独立立绘。
- 11件衍生装备进入现有 JSON 道具目录，并各自具备同ID回退资产；复用现有图标，词条、动画、音效继续走现有系统。
- 23个内置角色与8组首季对战进入主播编辑器下拉框；载入副本后可改双方、道具、数值、词条、动画、成长和吸收，再保存到个人预设或自定义怪物池。
- 普通青竹剑灵与赤丹药修不再默认携带固定四级核心；核心道具仍保留，可供觉醒版本和自定义影片使用。
- 八团史莱姆整套百分比成长收紧，保留一核心七粘液与先长血再造成自身生命伤害的身份。

这不是全角色达到50%胜率的声明。6件主题装会提高早期野怪整体难度，需要冒险通关数据确认；旧存档中记录的显式主播参数不迁移，仍引用目录的默认道具数值会更新。

## 下一步安排

|阶段|交付|验收与决定|
|---|---|---|
|P0 首季试录|先录8组预设，固定相同初始配置、交换左右，多次试打；每期只讲一个触发关系|观众能说清谁在何时因何机制逆转；记录时长、秒杀、拖入决胜、看不清的动作。若单一装备抢走全部戏份，先改数值|
|P1 角色包装|优先给最有表现力的3个新角色补独立圆球立绘和道具图标，再补片头卡、字幕关键词与剪辑模板|同屏缩小后仍能从轮廓认出角色；破盾、叠毒、转盾伤与普通直伤能区分|
|P1 实战平衡|同档六件装，1/2/4级、左右互换、至少20个种子；记录实际命中、有效回复、状态伤、最大生命曲线|异常强弱组合有可解释原因；同资源相近构筑以35%～65%作为复查带而非保证；跨档不追求五五开|
|P2 冒险闭环|角色主题掉落、分阶段装备解锁、觉醒首领、局内成长选择；先调好普通→精英→首领难度坡度|新玩家不用指定套路能过前段；拿到某角色道具能联想到视频中的角色；核心掉落没有越级碾压|
|P3 异步多人原型|快照上传/下载、同天数资源匹配、规则版本、身份与结果验证、断线与重试、最小排行榜|两个真实账号能够完成完整局；过期或被篡改的快照不进入排名；先休闲匹配，再开放排位|
|P4 赛季与房间|积分、赛季轮换、内容池禁用与版本锁定、8人赛事房间可行性|已有留存/对局质量数据支持投入；服务器成本和结果可信度达标|

多人实现前必须明确：服务器对结算的权威性、物理确定性或服务器重算方案、快照版本与资源预算校验、重复提交幂等、隐私与昵称处理。当前固定步与随机数序列是基础设施，不等于跨平台物理已确定，也不等于防作弊完成。

## 新内容交付契约

1. 道具定义遵循 `items.json` v2；使用唯一 `itemId`，`assetId` 明确指向资源资产。共享图片用 `iconId`，禁止借共享图片覆盖其他道具的数据。
2. 普通装备等级1～4，效果绝对表四个值；百分比用小数，单位秒。新词条设稳定ID；调数值不重建已有词条ID。普通、野外来源、首领身份分别配置。
3. 新道具使用现有触发类型：释放、命中、命中燃烧目标、破盾。注明目标、先后顺序、冷却、等级、成长归属及触发限制。若某机制无法用现有词条表达，先扩展共用战斗、详情、编辑器、序列化和测试，再宣布可用。
4. 内置角色写入 `characters.json` v1，以稳定角色ID引用；每个角色8个槽位，空槽显式保留。故事仅作内容资料，战斗字段仍采用 `PrototypeBroadcastSide`；无额外隐藏倍率。
5. 本批11件新装备都是商店+掉落、稀有、价格16、商店第2天起、权重2、无首领固定等级。图标和立绘复用是当前可见限制，不算专属美术完成。
6. 提交前检查：JSON与回退资产一致、图像存在、等级1/2/3/4真实释放、破盾触发、角色/对战往返序列化、怪物池缩放、编辑器选角换边换道具及保存重载、原回归检查。人工试录负责观赏性判断，自动检查不代替这一环节。
