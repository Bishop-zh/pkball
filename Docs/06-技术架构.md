# 技术架构

> 本文为总体架构。持久修正、Buff、事务 ID、固定步事件顺序与性能边界的实现细节见 [13-数值Buff与事件架构.md](13-数值Buff与事件架构.md)。

## 当前环境与边界

项目是 Unity 2022.3.62f3c1 URP 模板，已装 UGUI、TextMeshPro、Burst。首版使用 Unity 主线程物理与 C# 战斗模拟；Burst/Jobs 只在性能剖析确认瓶颈后用于纯数据批处理。游戏不依赖网络服务。全部配置先在本地 ScriptableObject 中维护，运行时状态和存档不直接改写资产。

## 定义、实例与规则

- `ItemDefinition`：稳定 ID、可本地化名称、稀有度、价格、标签、获取池、静态属性、效果配置、原型外观 ID。
- `ItemInstance`：唯一实例 ID、等级、随机词条、装备槽位 ID、剩余冷却、实例修正。
- `SlotDefinition`/`SlotInstance`：稳定槽位 ID、前后方标签、等级、格位附魔。格位效果与道具效果分开。
- `AugmentDefinition`/`AugmentInstance`：等级、出现条件、互斥组、修正命令、已选状态。
- `RunRules`：天数、格位成长、强化日程、商店权重、活动覆盖。活动以规则覆盖组合，避免复制游戏模式。
- `CharacterDefinition`：基础数值、起始道具、默认获取池、可用外观；`CharacterRunState` 保存锻体与本局修正。

ScriptableObject 是策划资产模板，不是玩家存档，也不是每件掉落道具的动态属性容器。每局的实例状态写入版本化存档 DTO，引用稳定内容 ID。皮肤只改变表现资源，不改变规则定义。内容校验工具检查 ID 重复、空池、循环合成、非法格位、超出上限等问题。

## 统一数值流水线

最终属性来自：角色基础值 → 本局锻体永久修正 → 强化 → 格位效果 → 道具被动 → 战斗 Buff → 软/硬上限。按固定顺序先平加、后百分比加、最后乘法修正；乘法来源按组叠加，以防多个倍率无界相乘。每一项保留来源 ID，UI 可显示数值明细。生命质量公式读取结算后的最大生命，但战斗中临时回血不改变质量。

## 战斗事件与高负载

连续运动和碰撞在固定物理步中进行；0.2 秒只用于部分道具的触发窗口，不把物理降到 5Hz。碰撞回调只记录紧凑结构体，不立即执行一串产生物体和 UI 的逻辑。每个模拟步依次处理：接触归并 → 基础撞击/武器伤害 → 护甲与 Buff → 生命变更 → 触发器 → 下一步新事件 → 死亡与结算。事件带来源、目标、模拟序号、连锁深度和随机种子。相同接触对在保护窗内合并；不同伤害来源不随意合并丢失。

触发器可声明 `Cooldown`、`Window=0.2s`、`MaxTriggersPerCombat`、`CoalesceMode`。例如在窗口内 12 次命中，“每 4 次发一针”产生 3 次效果；另一件“最多触发一次”的道具只触发 1 次。循环产生的事件放下一步队列，深度和预算超限时推迟并记录性能告警。伤害与死亡不能被经济窗口延迟到角色已经继续攻击。

视觉投射物、伤害数字和特效从对象池获取；逻辑伤害数据不要求每条都有 GameObject。视野内同时生成量设预算，超出时合并伤害数字或降级特效，**不丢弃真实战斗结算**。初版目标：普通战斗主线程保持 60 FPS，压力场景（两角色、100 投射物表现、每秒 2000 条逻辑事件）在开发机上记录耗时与 GC；若未达标先分析热点，再决定 Jobs/Burst、空间网格或批处理。

## 场景与依赖方向

`Bootstrap` 创建配置目录、随机服务、存档服务与运行状态；`Frontend` 负责局外与准备界面；`Combat` 场景负责物理呈现。规则层不引用 UGUI、材质或具体 Prefab。Presentation 监听只读战斗快照与表现事件，UI 监听本局状态变化。页面切换不能直接修改金币或物品列表，必须调用事务式命令服务。

## 可测试性

规则层尽量使用纯 C#，可固定随机种子跑批量模拟。最先覆盖：4→6→8→10 扩格映射、对位关系、碰撞保护窗、近战距离、远程无目标时保留冷却、经济上限、锻体效果顺序、强化活动覆盖和存档迁移。Unity 场景测试集中验证拖放、发射与表现绑定。版本号变动时保留旧存档迁移函数。
