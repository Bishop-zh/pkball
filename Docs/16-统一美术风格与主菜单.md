# 统一美术风格与主菜单

状态：本轮原型的**后续出图基线**。所有新增角色、怪物、道具、UI 图片先遵守本规范，再进入项目。此规范也适用于未来高级武器的 3D 概念图、贴图和图标。

## 一、视觉语言

- 方向：明快的奇幻机械卡通。主体使用简单的大轮廓和少量装饰，能在 128×128 小尺寸辨认。
- 绘制方式：有手绘材质的干净色块、柔和球面渐变和明确的左上方暖光。线条为近黑的深海军蓝，重要外轮廓较粗，内部线条略细。
- 固定材料：冷钢（角色护具）、暖黄铜（铆钉与边框）、彩色珐琅（法术与按钮）、木材（次级按钮）。材料光照一致，避免同套资源里突然出现照片写实、像素风、扁平无描边或硬核科幻。
- 主色：深海军蓝 `#10243C`、青蓝 `#19BCCE`、暖黄铜 `#D99832`、珊瑚红 `#DB504A`、奶白 `#FFF1D1`。法师可辅以紫色，怪物可辅以苔绿；同一元素的主色最多两种。
- 角色比例：角色就是一个大圆球，不含独立四肢、躯干或腰部。球面占主体可见面积的 70～85%，圆心核心完整；附件视觉面积最多 25～30%，角、帽、面罩、小口袋紧贴球面。眼睛发光，角色识别来自球面五官、材质和少量贴身饰件。常态武器缩为小标记或小饰件，禁止持大武器站立成胖人形、长披风垂地或满身杂乱尖刺。战士青蓝、法师紫青、工程师琥珀色；普通怪物苔绿、精英珊瑚红、首领深紫。
- 背景：远景低饱和、低对比，界面组件高对比。不要在标题与模式卡文字区域叠加高频背景细节。

## 二、出图和技术要求

1. 道具和角色均用真正的透明 Alpha PNG。主体单独居中，边缘留至少 6% 透明安全边距；**禁止**圆形徽章、色块底牌、棋盘格假透明、投影地板、文字和水印。角色可以有贴身阴影，不制作独立地面阴影。
2. 角色按 3×2 合批，每格裁成 512×512 真透明 Alpha PNG。同批保持相同机位、球体直径、线宽、左上暖光和材质笔触。武器和附件留在各自裁切格内，不进入隔壁格。怪物按角、口型、盔甲递增复杂度，而不是只缩放或换色。
3. UI 图集只包含无字组件，标题与按钮文字由 UGUI 绘制。图集切片应保留完整透明边界，控件用等比缩放；需要拉伸的后续组件须单独设计九宫格安全区。
4. 导出源图集到 `Assets/PKBall/Art/Generated/`；运行时裁切图到 `Assets/PKBall/Resources/Art/` 或 `Resources/UI/`。角色裁切为 512×512，UI 切片按原图比例，背景为 1920×1080。保持文件名和资源 ID 稳固；替换皮肤只改 `PrototypeVisualDefinition` 的图片引用。
5. 生成后先在透明底和深浅两种底色上检查：是否有毛边、邻格残片、伪透明、文字、裁切、比例失衡。再在 128×128 缩略图检查武器与角色可辨性。最后在 Unity 的 16:9 与 16:10 窗口检查菜单留白、文字、点击区。

### 统一提示词骨架

> Playful fantasy-mechanical cartoon spherical creature; one large intact round ball as the entire body, 70-85% visible spherical surface; no separate torso, waist, arms, hands, legs or feet; tiny close-fitting horns, cap or pouch, total attachments at most 25-30%; glowing eyes; no large held weapons or floor-length cape; clean hand-painted textured shapes; thick dark navy outer outline and thinner inner lines; saturated cyan, amber brass and coral accents; cool steel and warm wood; soft top-left highlights; readable silhouette at 128 px; one centered isolated subject; true transparent alpha; same perspective and line weight as existing PKBall character and item atlases; no text, watermark, badge, tile, fake checkerboard, photorealism, pixel art, extra background or unrelated objects.

每次只补充**物品或角色的形状、材料、动作和配色**。生成 UI 背景时把透明要求改成完整 16:9 场景，同时要求文字留白和低对比远景。

## 四、主菜单结构与跳转

本版参考用户提供截图的**信息层级**：顶部居中大标题，下方并列大模式卡，左侧旅程档案，右侧外观选择，远景山谷作为留白背景。所有图片、文字、角色和图标为本项目原创风格。

```text
主菜单
 ├─ 顶部：游戏名称 / 英文短标题
 ├─ 中央：匹配模式（可进入）/ 休闲模式（后续开放）/ 双人模式（后续开放）
 ├─ 左侧：天数、胜场、耐力、金币；图鉴与排行状态说明
 └─ 右侧：战士、法师、工程师外观；本地模拟对手说明
       ↓ 匹配模式
准备阶段（已有商店、背包、事件、格位、野怪选择）
       ↓ 开始战斗
弹射战斗 → 结算 → 下一阶段准备
       ↖ 准备阶段可返回主菜单
```

“匹配”在这一原型中接入现有的本地对手与天数流程，不计算排名、服务器积分或真人配对。排行榜、多人模式的卡片只作信息预留，没有虚假的点击结果。右侧角色是皮肤入口，战斗构筑依旧从白板开始。未来角色池和真人对手接入时，扩展菜单控制器和对手提供者，不把后端逻辑写进 UGUI 组件。

球体角色的造型边界、六角色图集约定与验收详见 [36-球体角色美术规范.md](36-球体角色美术规范.md)。

## 五、后续资源扩展

- 新外观：增加一张 512×512 透明图、对应 `PrototypeVisualDefinition`，菜单角色列表由配置驱动后再扩容；怪物等级仍由对手数据决定。
- 高级武器 3D：模型保持图标的体积比例和色板，URP 材质采用同一黄铜、钢、珐琅方案；UI 图标仍单独绘制，并通过道具视觉配置引用模型。
- UI 适配：现阶段以 1920×1080 为参考分辨率，CanvasScaler 等比缩放；后续新增画幅时保持标题、模式卡和左右侧栏的安全区域，不用直接拉伸图集边框。
