# 状态边界与统一战斗调度

2026-10-12。接续 `39-架构审查与基础治理.md` 的第二轮实现。本轮优先完成状态边界、持久化战斗结算标识、统一数值推进、持续飞剑逻辑独立，并补充属性来源与场景回归。保留了文档 37 已确定的“再次召唤时全剑齐射”。

## 已落地的规则边界

`PrototypeRun.Lifecycle.cs` 维护 Preparation、Aiming、Fighting、Resolving、Ended。一天的六个 DayStage 仍独立存在，分别表达不同层级的状态。

准备入口共用 `CanEditPreparation`，瞄准、战斗、结算、封存、结束时不能购买、装卸、出售、合成、吞并、移动物品、刷新商店、领取产物、使用药水、升级或推进事件。取消瞄准后恢复准备操作。被阶段检查拒绝时，库存、金币、Version 和存档内容保持不变。

Bag、PendingRewards、Equipped、Shop、SlotEffects、PermanentModifiers、PendingBattleModifiers 都改为私有容器和缓存的只读视图。UI 可以读取和遍历，不能直接增删或替换元素；测试构造旧档/坏档的入口集中在 Editor 的 `PrototypeCheckFixtures`。**这不是深度不可变快照**：ItemInstance 仍由战斗逻辑更新，其公开字段后续仍需收口。

## 战斗 ID 与 v8 存档

- `StartCombat` 返回成功与否；已有战斗期间重复调用不会清空产物、矿石、成长或下一场药水。显式传入已提交的 battleId 会被拒绝。
- `ResolveCombat(battleId, won)` 检查当前战斗身份，旧结果不能结算新战斗。现有 bool 重载用于同步调用；异步回调必须使用带 ID 的重载。
- 已提交的 battleId 随存档 v8 保存；同一收益不会在重复 Commit、恢复后再次开战或过期结果到达时重新发放。
- 正常完整结果结算期间，不写“只提交产物而还没更新胜负”的中间检查点，离开 Resolving 后写最终状态。历史快照标识战斗已经提交，避免被当作进行中的战斗再次恢复。
- 兼容 v1～v7。旧的中断战斗获得稳定的迁移标识；仍按既定设计只恢复已保存的成长/产物，不恢复物理战斗、不自动增加胜场。
- 新增自定义怪物的加载前验证；Unity 将内置怪物的空自定义槽反序列化为空对象时正确忽略，不再在读档后选怪时报“预设参数无效”。声明了自定义怪物 ID 却缺少对应快照时拒绝载入。
- 保存使用原有临时文件+原子替换。遇到 IOException 时最多追加三次短重试，保持旧文件；仍然失败由 Flush 报错，不通过删除旧档降级。

边界：持久化幂等目前覆盖**战斗收益与结果身份**，尚未覆盖购买/合成等每一种准备命令。结果处理仍不是通用的异常回滚事务；载入也尚未改成整体候选 RunState 的原子交换。不能将这些改变描述成“事务架构全部完成”。

## 战斗推进顺序

现在 Actor 和 Projectile 都没有独立的战斗 FixedUpdate。Battle 每步执行：

1. 整数 StepIndex 加一，以双精度累计的战斗时间更新 Elapsed。
2. 双方 Buff 到期。
3. 双方朝向、运动恢复、能量消耗和耗尽伤害。
4. 消费上一轮物理模拟收集的角色接触：按角色 ID 规范化、同对归并并固定顺序结算。
5. 双方状态跳数、生产与装备释放。
6. 延迟攻击、普通弹体、持续飞剑。
7. 检查点、决胜伤害、胜负判定。

Unity 的物理模拟在 FixedUpdate 后运行，因此物理接触在**下一个固定步入口**提交，延迟不超过一个固定步；不再在回调里写角色生命。墙面反弹仍是物理适配逻辑，会在物理回调中调整 Rigidbody。这里没有替换 Unity 的物理系统，也不承诺跨平台逐位确定性。

战斗暴击使用独立 `PrototypeCombatRandom`，由 battleId 稳定派生种子，暴露种子和随机序号，不再消耗 Unity 的全局随机流。商店、掉落与生产抽样仍使用本局随机逻辑，不属于完整可恢复随机服务。

最近 256 条真实伤害记录保留 eventId、step、目标、伤害、类型和 RNG 序号。读取记录时返回副本，写入时不进行逐事件分配。记录仅用于诊断，不是带 originEventId/chainDepth 的通用战斗事件总线。

## 普通弹体与持续飞剑

普通弹体延续第一轮的逻辑队列。新增 `PrototypeSwordFlight` 保存每把飞剑的独立位置、索引、弹速、起手延迟、攻击/穿刺/环绕计时；每把剑各自持有释放时的伤害快照。

`PrototypeProjectile` 现在只呈现图像、朝向、拖尾，不再决定移动或提交伤害。每方最多 16 把可见剑，超过后的逻辑剑仍独立推进；不再把多把剑伤害加到某个可见代表上。新增剑继续让该角色全部逻辑剑齐射，命中后仍为 2.4 秒再次攻击，加实际飞行时间。原有显示合并引起的命中时间变化由此消除，超过 16 把时的战斗表现可能与旧实现不同，这是此次修复的目标。

`ProjectileVisualsEnabled=false` 可在测试中关闭新弹体的显示分配，逻辑继续运行。释放后切换该开关不会自动隐藏已存在的显示对象；它是分配开关，不是游戏暂停或逻辑预算。

角色死亡、目标死亡和战斗结束都会清除对应逻辑与显示；主播结束也提交当前战斗，再次开战使用新 battleId。场景重建的中断路径补齐了收益提交，防止复用 Run 时永远留在 Fighting。

成本现在随逻辑剑数增长，显示仍有预算。尚未对极长局无限召唤设置经过玩法确认的逻辑容量上限，也没有声称这一方案满足每秒 2000 事件的性能目标。后续优化只能在保持逐剑时序和反应等价的前提下合批。

## 属性与 Buff 的本轮收口

- 配方速度、撞击、增伤等写入按来源的 Buff 记录；减伤按来源保存累计贡献，保留 `1 - 乘积(1 - 减伤)` 的旧数值语义。
- 源键包含装备实例 ID，可移除某一来源而保留其他来源。
- `BuffManager.GetSnapshot()` 返回只读字段的独立记录数组，供诊断或后续 UI 使用；到期和来源移除不依赖减回旧字段。
- `PrototypeStatCalculator.AddEquipment` 同时用于主模式和主播模式，包含继承属性、实例永久撞击成长与可选格位加成；消除主播属性构造中的重复公式和遗漏。
- 当前保留初始化质量快照的玩法。无敌依然是独立时间字段，盾/毒/火/再生仍按类型聚合；尚未实现通用 BuffDefinition、全部叠加策略与所有属性统一快照。
