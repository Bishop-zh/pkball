## 批处理与性能说明

- UI组件共用 CombatInterface 图集，新旧物品图标共用 CombatItems 图集；关闭旋转与紧密打包，4px padding，无 mip，默认 UI 材质。
- 组件分离方便换肤；减少 draw call 依赖共享纹理/材质与绘制顺序，不能仅凭“拆开”保证。字体、裁剪、相互穿插的 UI 层及特效可能打断批次。
- 大背景、地面和圆边单独存储，避免把大尺寸低频资源塞进 UI 图集造成多页和浪费。地面世界 Sprite 与 UGUI 也不共享一个批次。
- 首轮中央场地以 1024×1024 RenderTexture 显示，解决圆盘、背景与前景 UGUI 的绘制关系；使用一份视口贴图，退出时释放。它增加一次离屏渲染成本，不能宣称单凭这个降低总 GPU 成本；后续可对比直接相机视口方案。
- 冷却使用 Filled Image，无独立每格贴图；每帧只更新必要遮罩和生命条，文字节流到 10Hz，装备列表按 Run.Version 重新绑定。
- 本轮不声称已经量化减少多少 draw call；后续需在目标构筑下用 Frame Debugger/Profiler 对比批次、CPU UI重建和 GPU耗时。
